# motosh.dev

Портфоліо Марка Цимбала. Статичний сайт без збірки: чистий HTML, CSS і ES-модулі.
Уся візуальна мова походить із `design-system/` — цей каталог є джерелом істини, а не довідкою.

## Сторінки

- `/` — головна;
- `/cases/fdu/` — кейс Федерації Дзюдо України (запущено);
- `/cases/fspu/` — кейс Федерації сучасного п’ятиборства України (працює на `dev.fspu.org.ua`);
- `/cases/platform/` — кейс системи проведення змагань (у розробці).

## Локальний запуск

```bash
py -m http.server 4173
```

Сайт буде доступний на `http://127.0.0.1:4173/`.
Стенди тягнуть живі сайти (`ukrainejudo.com`, `dev.fspu.org.ua`, `app.ukrainejudo.com`), тому потребують інтернету. На мобільному вони завантажуються лише за тапом, щоб не витрачати трафік без попиту.

## Архітектура: дві верстки під одним капотом

Мобільна версія — не набір медіа-запитів поверх десктопної, а **окрема верстка**.
Обидві живуть в одному документі й ніколи не застосовуються одночасно.

```
design-system/variables.css   токени (джерело істини)
assets/core.css               спільний шар: @layer, reset, примітиви, контракт руху
assets/desktop.css            повна десктопна верстка   media="(min-width: 900px)"
assets/mobile.css             повна мобільна верстка    media="(max-width: 899px)"
```

Розмітка форкається лише там, де вона справді має відрізнятися: блок із
`data-layout="desktop"` або `data-layout="mobile"` прихований у шарі `base` і
вмикається назад усередині відповідної верстки. Текст і заголовки спільні —
дублювати контент заради адаптації немає сенсу.

JavaScript влаштований так само:

```
assets/core.js       спільне ядро + вибір верстки через matchMedia
assets/desktop.js    монтується лише на десктопі
assets/mobile.js     монтується лише на мобільному
```

Перехід через брейкпоінт демонтує активний модуль (кожен підписник живе у
`Disposer`) і монтує інший — жодних слухачів-привидів.

## Інтерактивні блоки

| Модуль | Що робить |
|---|---|
| `field.js` | Амбієнтна сітка на canvas: шум + відштовхування від вказівника (на мобільному — від дотику й нахилу) |
| `rig.js` | Стенд пристрою — сайт рендериться у справжній ширині вікна й масштабується під сцену |
| `wiring.js` | Карта інформаційної архітектури та контентна модель зі SVG-зв’язками |
| `bracket.js` | Турнірна сітка: три етапи змагання та підсвітка шляху спортсмена (пройдене — суцільним, майбутнє — пунктиром) |

Поле в героях відстежує вказівник на `window`, а не на своєму шарі: контент
лежить поверх канваса, тому наведення на заголовок чи кнопку раніше кидало
`pointerleave` і гасило ефект. Сила ефекту наростає й згасає експоненційно
(140 мс / 520 мс), тому в кривій немає кута — раніше лінійне згасання
обривалося ривком.

## Розширення дизайн-системи

Опублікована система має вісім фіксованих кеглів і фіксовану шкалу відступів —
цього не вистачає для флюїдної верстки від 375 до 1440 px. Замість того щоб
розсипати `clamp()` по двох стилях, усе зведено у названі токени в `core.css`:

- типографіка: `--text-display-xl`, `--text-display-lg`, `--text-section`;
- ритм: `--gap-sm/md/lg/xl`, `--section-pad`;
- рух: `--dur-0…4`, `--ease-*`;
- `--hairline` — 1px-волосінь, коли вона малюється через `gap`.

Нових кольорів, радіусів і поверхонь немає.

## Контракт руху

Головне правило: **числа не анімуються — анімується корпус**. Показники
(мілісекунди, відсотки масштабу) змінюються миттєво, а корпус, який їх тримає,
плавно переїжджає. Плавно рухаються лише панелі, шторки, каркаси й ручки.

Увесь безперервний рух іде через один `requestAnimationFrame` у `core.js`:
підписники додаються в `ticker`, і цикл сам зупиняється, коли нікому не потрібен.
Пружини інтегруються з фіксованим кроком 1/60, інакше фізика на 120 Гц ішла б
удвічі швидше, ніж на 60 Гц.

## SEO

Базові технічні перевірки закриті на всіх чотирьох сторінках:

- унікальні `title` й `description` (усі до 160 символів), канонічні адреси,
  `hreflang` з `x-default`, повний набір Open Graph і Twitter (включно з
  розмірами та `alt` зображення);
- структуровані дані одним `@graph` на сторінку: головна — `WebSite` +
  `Person` + `ProfilePage` + `ItemList` робіт; кейси — `BreadcrumbList` +
  `WebPage` + `CreativeWork`, зв’язані з автором через `@id`;
- `sitemap.xml` і `robots.txt` актуальні, усі сторінки індексуються;
- жодного зображення без `alt`, жодного посилання без `href`, один `h1` на
  сторінку, ієрархія заголовків без пропусків.

Дві мобільні перевірки, які найчастіше валять оцінку, вимірювалися вручну
в браузері, а не на око:

| Перевірка | Було | Стало |
|---|---|---|
| Тап-цілі ≥ 48 px | 25–26 замалих на сторінку | 0 |
| Частка тексту ≥ 12 px | 74 % | 82–89 % |

Тап-цілі піднято до 48 px разом із проміжками (сусідні цілі не мають
перекриватися зонами дотику). Мінімальний кегль моно піднято до 12 px — це
всередині документованої моношкали 10–13, тож дизайн-система не порушена.

## Заміна портрета

Підготуйте вертикальне фото ≈ 3:4, збережіть як `assets/portrait.webp` і
замініть шлях `/assets/portrait-placeholder.svg?v=1` в `index.html`.

## Локальна UX-аналітика

Сайт анонімно зберігає у `sessionStorage` поточної вкладки кліки, переглянуті
секції, глибину скролла й активний час. Нічого не надсилається назовні.
Перегляд: `portfolioAnalytics.read()` у консолі.
